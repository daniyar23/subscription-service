# ADR-001: Использование трёхслойной архитектуры

## Статус
Принято

## Контекст
Необходимо спроектировать REST API для управления подписками. Важно обеспечить читаемость, тестируемость и расширяемость кода.

## Решение
Использовать трёхслойную архитектуру:
- Handler (HTTP слой)
- Service (бизнес-логика)
- Repository (работа с БД)

Между слоями используются интерфейсы.

## Причины
- Разделение ответственности
- Упрощение тестирования (можно мокать интерфейсы), но в рамках этого задания,я не делал явные тесты, а только в процессе разрбаотки 
- Гибкость при замене реализации (например, БД)

## Последствия
+ Чистая структура проекта  
+ Удобство масштабирования  
- Больше кода по сравнению с монолитным подходом
